## Legacy save containment evidence

- The Android and iOS legacy progress bridges no longer hold a remote client or invoke save/state upload, download, or manifest reconciliation. Their launch/refresh paths use local files; explicit legacy sync/adopt requests report unavailable without advancing last-successful-sync metadata. Generic API upload endpoints remain available for the forthcoming protocol transport, but there are no application legacy publication callers.
- Local continuity changes and manual upload/delete intent survive attempts to sync. Android parks queued non-core actions before marking them running or replaying slot deletion, avoiding deletion of a subsequently saved slot. Tombstones commit before unlinking files; refresh and the state browser honor them even when old bytes or rows remain after interruption.
- Slot zero and old aliases are preserved during import. Differing aliases are not deleted. Legacy automatic recovery replacement is atomic. The local-only UI status is explicit even when historical journal rows contain a previous sync timestamp.
- Regression coverage: Android `LegacyProgressContainmentTest` (four cases), an interrupted-deletion browser case in `GameStateRecoveryTest`, and iOS `RommSyncBridgeTests` (three cases).
